## 2. 资源解码与字体

- `d.a(byte[], byte)` 的算法为 `明文[i] = 密文[i] XOR ((初始密钥 + i) & 255)`。文本入口使用初始值 77（`d.java:385–390`、`d.java:908`、`d.java:1075`）。
- `d.b(byte[])` 的封装格式为：前 2 字节大端长度、第 3 字节初始密钥，随后复制指定长度数据再执行上述 XOR（`d.java:1945–1953`）。`lz.png` 通过它恢复后交给 `Image.createImage`（`e.java:4053–4055`）。该过程没有压缩步骤；不能把所有二进制笼统称作“压缩”。
- `hd.png` 是图片索引入口（`e.java:1798–1801`）。图片索引项使用 2 字节偏移和 2 字节长度；读取时偏移减去当前包累计基址 `bd`（`e.java:1705–1708`）。该双字节转换为大端（`e.java:4026–4027`）。
- `pck0/1/2` 被按三个编号范围载入，并累计包长（`e.java:1585–1595`）。提取器必须复现包基址，不能把全局偏移直接用于每个分包。
- 字体 `cf.png` 读取 600 字节，组织为 100 条 × 6 字段。结合绘图可判定字段为图集 x、y、宽、高、水平偏移、基线方向偏移；`fnt.png` 是图集（`d.java:362–380`、`d.java:434–444`）。字段在 Java 中是有符号 byte，导出时不能全量无脑转无符号。
- 字符映射先把英文小写转大写，再减 32；非法索引回到 0。源码还包含俄文字母范围映射（`d.java:666–677`）。英文版仍应保留原始 0–99 索引以便对照，不必把所有格子都解释为英文字符。

建议验收产物：原始索引表、字段解释、带索引和字符标签的字形总览、独立字形图。保留位移和字距，避免只裁剪可见像素后改变排版。

## 3. 地图拼接

### 已确认格式

- 单瓦片 16×16 像素（`e.java:1488–1489`、`e.java:3316–3320`）。模块为 4 行 × 4 列、共 16 个瓦片编号（`e.java:107–108`、`e.java:161`）。
- `ll.png` 每关固定读 819 字节，偏移为 `(关卡号 − 1) × 819`（`e.java:1247`）。头两字节分别是地图列数减一、行数减一（`e.java:1486–1487`）。
- `obg.png` 读取 1344 字节；按每模板 16 字节计算可容纳 **84 个模板**，实际文件长度已核实；84 是按记录大小推得的容量，各模板内容尚未逐一核验（`e.java:1506`、`e.java:1517`）。
- 关卡块从偏移 309 开始读取 170 个三字节记录：`x、y、模块编号`；编号 0 表示不放置，其他编号使用 `(编号 − 1) × 16` 索引模板（`e.java:1512–1518`）。源码对 x 和编号做无符号转换，对 y 保留有符号 byte，提取时要分别处理。
- 模板第 `r` 行落到内部地图行 `地图高度 − y − 1 − r`，第 `c` 列落到 `x + c`。越界格跳过，只有目标当前为 0 且模板格不为 0 时才写入，因此**先出现的非零格优先**（`e.java:1518–1544`）。内部 y 轴与最终屏幕 y 轴方向不同，不能把模板行序变化误认为旋转。
- `ax` 模式会把若干瓦片编号替换为其他编号（`e.java:1528–1539`）；后续已确认该标志是低内存模式：Runtime.totalMemory() 小于 250000 时开启（e.java:792–796）。当前导出使用完整素材模式。
- `N` 同步保存 0、8、16 等数值（`e.java:1545–1550`），碰撞判断使用“瓦片行 × 16 + N”作为高度（`e.java:854`）。**推断：这是每格的碰撞/支撑高度数据，而非单纯布尔障碍掩码。**

### 完整地图不能只做模板贴图

对象初始化 `i()` 在地图拼接后调用（`e.java:1656`），它继续改变碰撞数据、地图编号和邻接瓦片；例如 `e.java:1064–1096`、`e.java:1121`、`e.java:1138–1140`。运行期间还有地形变化（例如 `e.java:2811–2844`）。

瓦片可为空图像但引用两张子图；底图与带偏移的叠加图一起渲染（`e.java:3322–3329`）。`b(int,int)` 在 170–219 的运行时编号区间创建/复用组合引用（`e.java:447–465`）。另有邻接修补和随机装饰逻辑（`e.java:1852–1925`）。

建议分别导出基础模板拼接图、对象初始化后的场景图、碰撞高度图和对象坐标清单。所谓“完整地图”应注明是否包含对象和随机装饰；单张背景图不等于可用关卡数据。当前未找到运行时地图旋转证据，后续以资源和画面对照确认，而不是先实现旋转系统。

## 4. 精灵、组合物体与程序绘图

- `cu.png` 使用 6 字节记录描述图像及位移；`upN`、`zpN` 加载两套图像。前三字段均为 255 的记录复用已有图像（`e.java:1761–1789`）。
- `bz` 共 310 项，另一方向使用 `编号 + 155`；方向变化时位置公式同步改变（`e.java:1598–1600`、`e.java:3824–3829`）。这直接证明运行时读取两套方向资源，尚不能证明资源内容一定只是严格镜像；导出时应保留两套原图。
- `ca.png` 为 680 字节，生成 85 个组合帧，每帧最多 8 个部件编号，另外计算高度（`e.java:1663–1685`）。绘制按部件顺序叠加，使用各自锚点（`e.java:3812–3834`）。
- `cc` 记录里宽高为零时，两个位移字段也可被解释为两张子图引用，不能只按普通偏移字段导出（`e.java:1711–1742`、`e.java:3847–3855`）。
- 手绘效果实例：椭圆阴影（`e.java:3505–3508`），叠加部件和随机线段/闪烁颜色（`e.java:3564–3595`），多层圆角矩形（`e.java:3652–3668`），红色线段动画（`e.java:3699–3712`），三角指示符（`d.java:514–520`、`e.java:3740–3743`），画面平移震动（`e.java:3305–3312`）。
- 部分绘制函数直接更新动画计数/状态（`e.java:3538–3548`、`e.java:3717–3728`）。重构若改为固定更新步长，需要明确保留原本的动画节奏，而不是把绘制函数原样复制。

建议：静态组合和离散组合帧可以离线烘焙，同时保留部件清单、锚点和绘制顺序；随机线段、震屏等随状态变化的效果用简单绘图逻辑重建。未完成资源预览前不建议全部烘焙为图片，也不建议建立通用复杂特效引擎。

## 5. 富文本语义

| 原编码 | 已确认作用 | 证据 |
| --- | --- | --- |
| `[` | 后续行按左对齐布局 | `d.java:979–981`、`d.java:1248–1258` |
| `\|` | 居中 | `d.java:1019–1021`、`d.java:1251–1254` |
| `]` | 右对齐 | `d.java:982–984`、`d.java:1255–1257` |
| `{` | 显式换行/结束当前行 | `d.java:1004–1018` |
| CR | 提交当前行，并额外跳过一个字符，符合 CRLF 输入 | `d.java:929–944` |
| `^` 后跟 1 个字符 | 图像索引为“后继字符编码 − 32”；产生图像行，可与后续文本共同排版 | `d.java:985–1003`、`d.java:1260–1282` |
| `}` | 文本有效内容终止；解码后先扫描截断到它之前 | `d.java:910–918` |

自动换行按实际字形宽度累计，空格、逗号、句号可成为折行点（`d.java:945–977`）。当前导出使用可读文本与简短标签，并通过反向还原控制符校验。标题后 CRLF 与正文换行分开处理：第 0 行由 `d.java:1216` 附近单独绘制，滚动正文从第 1 行开始；标题分隔不增加正文高度。图片命令隐含的另起一行导出为显式 LF。详见 [文本格式](runtime-assets.md#文本格式)。

另一条文本路径 `tt.png` 是 XOR 后按 CRLF 分行、按 `=` 拆列的字符串表（`d.java:1073–1123`、`e.java:4031`），不应与富文本页面使用同一个解析器。
